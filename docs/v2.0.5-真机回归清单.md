## B. 网络与鉴权失败

每个场景至少选择一个自动查询源执行；401、429 和超时应优先覆盖 Codex，并再覆盖一个公开余额 API。测试前必须已有新鲜成功缓存。

### B1. 断网

- [ ] 开启飞行模式或断开所有网络后刷新。
- [ ] 有效期内的成功数据显示为“缓存数据”，余额值不被清零，成功时间保持上次成功时间。
- [ ] 没有缓存或缓存过期时显示明确异常，不显示伪造的 0 余额。
- [ ] 恢复网络后下一次刷新恢复成功状态并更新成功时间。
- 结果：待执行 / 通过 / 失败

### B2. 401 未授权

- [ ] 临时换成明确无效的测试凭据，或在测试账号控制台撤销专用凭据；不要破坏唯一生产凭据。
- [ ] 有新鲜缓存时回退并标记“缓存数据”；无有效缓存时显示鉴权异常。
- [ ] 恢复有效凭据后能够自动恢复，不需要清除设置、历史或重新安装。
- 结果：待执行 / 通过 / 失败

### B3. 429 限流

- [ ] 使用受控代理返回 HTTP 429；不得通过密集请求真实服务制造限流。
- [ ] 有新鲜缓存时回退为“缓存数据”，组件仍能完成渲染。
- [ ] 无有效缓存时显示异常，其他数据源不受影响。
- [ ] 记录从刷新到组件完成的耗时，确认没有持续重试或卡死。
- 结果：待执行 / 通过 / 失败

### B4. 超时

- [ ] 使用受控代理延迟响应超过主请求的 15 秒超时；图标下载可另行延迟超过 10 秒。
- [ ] 余额超时后按缓存规则降级，其他并行数据源正常显示。
- [ ] 图标超时只回退到字母标志，不影响余额与组件完成。
- [ ] 记录首次无图标缓存和已有图标缓存两种情况下的总执行时间。
- 结果：待执行 / 通过 / 失败
